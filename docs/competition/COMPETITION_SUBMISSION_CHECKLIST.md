# 大赛提交核对表

## 1. 代码仓库

| 要求 | 当前状态 | 提交前动作 |
|---|---|---|
| GitHub / Gitee，Public 或提供访问权限 | 仅有本地工作区 | 上传到团队真实仓库并设置评审访问权限 |
| 代码结构清晰、注释有效、遵循主流规范 | 已具备目录结构、README、测试和模块注释 | 提交前运行格式与静态检查 |
| README 包含项目介绍、架构、安装、团队信息 | 已包含，团队信息仍为“待填写” | 填写真实团队信息 |
| 完整 Git 提交历史 | 当前工作区未检测到 `.git` | 从已有真实开发仓库上传或迁入历史，不伪造记录 |
| 环境变量模板与依赖清单 | 已有 `.env.example`、Python 与前端依赖文件 | 确认 `.env` 未进入公开仓库 |

公开前检查：

```powershell
git status
git log --oneline --graph --all
git check-ignore -v .env samples/auth.local.yaml
rg -n "sk-[A-Za-z0-9]|api[_-]?key|password=|JWT_SECRET=" -g "!*.lock" -g "!node_modules/**" .
```

不要提交：

- `.env`
- `samples/auth.local.yaml`
- 真实 API Key
- 管理员密码
- 客户或学校敏感授权材料
- 运行时输出、证据和数据库文件

## 2. 演示视频

| 要求 | 当前状态 | 提交前动作 |
|---|---|---|
| MP4，不低于 1080p | 脚本已完成 | 使用 1920×1080 或更高分辨率录制 |
| 5-8 分钟 | 已按 7 分钟设计 | 录制后核对实际时长 |
| 普通话讲解，可配字幕 | 讲解稿已完成 | 真人录音或合规 TTS，并校对字幕 |
| 项目介绍、核心功能、AI 亮点 | 分镜已覆盖 | 按脚本录制并保留真实操作过程 |

录制文件建议命名：`团队名称-攻击面扫描系统-演示视频.mp4`。

## 3. 技术文档

| 要求 | 当前材料 |
|---|---|
| PDF 格式 | `传智杯-攻击面扫描系统-技术文档.pdf` |
| 不超过 30 页 | 18 页，13 张互不重复的图 |
| 项目概述、需求分析 | 第 1-2 章 |
| 系统架构设计 | 第 3-5 章 |
| AI 技术方案、选型、集成、优化 | 第 6 章 |
| 核心功能实现 | 第 7-8 章 |
| 测试与部署 | 第 10 章 |
| 总结与展望 | 第 13 章 |
| 技术创新点与应用创新点 | 第 12 章 |

提交前将第 14 页与封面中的团队信息从“待填写”改为真实信息，再重新导出 PDF。

## 4. 在线演示

该项为可选加分项。若选择提交：

- 提供公网可访问地址。
- 评审期间保持服务可用。
- 提供专用账号，不提供个人管理员密码。
- 限制扫描目标和速率，避免被公网滥用。
- 准备演示数据的备份快照。

## 5. 最终提交顺序

1. 填写 README 与技术文档中的团队信息。
2. 确认 `.git`、提交历史和仓库访问权限。
3. 完成 1080p MP4 演示视频与字幕。
4. 复核技术文档页数和 PDF 中的图表。
5. 检查所有敏感信息。
6. 通过大赛官网统一提交。

提交后不得修改；如遇特殊情况，联系组委会处理。
